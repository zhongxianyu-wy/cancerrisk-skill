## 2. 目标产物形态（最终 skill）

一条**单报告管线**：体检文件 → OCR → 苏格拉底式高危因素收集 → 健康总结分析 + 快照癌症风险预测 → **唯一整合体检方案报告**，并维护个人健康档案 + 可选单指标纵向视图。

**癌种范围**：沿用 v1.3 的 15 癌种（肺/肝/胃/食管/结直肠/乳腺/宫颈/前列腺/膀胱/卵巢/肾/头颈/胆道/甲状腺/胰腺），以 `database_new` 知识为准重建。

---

## 3. 架构（在 v1.3 管线上的外科化改造）

沿用 v1.3 orchestrator `run_formal_analysis.py` 的检查点（checkpoint）骨架，按 spec §2 调整阶段：

```
0  环境检测与配置（env_check：校验 evidence store + KB + 模版）
1  MinerU OCR → 各文件 content.md
2  [CP1] LLM 精炼 refined.md（保留人口学/异常行/肿瘤标志物/影像结论/阳性发现）
3  [CP2] 苏格拉底式高危因素收集（interactive 问卷，含遗传 BRCA/Lynch；真实运行不得跳过）
4  LLM 汇总提炼：全部检测结果 → 结构化档案 md（带时间标签 + 用户ID）
5  LLM 异常指标提炼 md
6  异常指标 → 健康总结 API → 返回 md（保留为内部分析）
7  [CP3] LLM 把异常指标匹配到癌症风险证据库，取每癌的风险证据（初次提取 + 第二次审核补充）
8  [CP3.1] 独立审核（PUA）：复核遗漏/被拒记录
9  贝叶斯脚本计算每癌后验概率（记录每个因子升高风险的程度）—— snapshot_risk.py（D2 兼容）
10 [CP5] 生成唯一整合报告（模版 §5），含非癌异常指标的复查 + 癌症对应筛查
11 个人健康档案入库（CP-archive）
（可选）单指标纵向视图：按需调用，独立小输出/区块
```

**改造点 vs v1.3**：删除三个独立 HTML 渲染器作为交付（`render_health_summary`/`render_snapshot_html`/`render_longitudinal_html` 退化为内部数据或删除）；新增单一报告渲染器；新增单指标纵向（可选）。

## 4. 数据层（spec §4 双表征 + §8 缺口补充）

从 `database_new/` 重塑，去冗余，**两套表征各司其职**：

- **MD 知识库（按需加载）**：用于筛查推荐解读。按癌种 + 专题组织（已有 21 个 MD）。严格"按需加载"——report 阶段按命中的癌种/异常只读相关 MD。供 LLM 参考解读复查项目、价格、周期。
- **结构化文件（引擎调用）**：用于癌症风险预测/贝叶斯。保留 `evidence_store` 兼容 schema（ontology/assertions/screening/voi/interaction），精简冗余字段、重建派生数据。

**§8 缺口流程**：① 先做架构-知识对齐分析（列出唯一模版 §5 各板块 + 各功能模块需要哪些数据：风险因子 OR/RR、检测灵敏特异、筛查技术/价格/周期、液体活检性能、遗传证据）；② 标出 `database_new` 与该需求的差集；③ 仅对缺口用 `WebSearch` 调研补充（带来源）；④ 按功能对齐重塑落库。**不得编造数值**——所有 OR/RR/LR/灵敏特异/价格/周期必须有 MD 字面出处或检索来源。

## 5. 唯一整合报告模版（spec §7，锚定 `temp/html-preview-2`＝阴性 / `-7`＝阳性）

**同一模版、两种液体活检状态**。板块（顺序固定）：

1. **报头 + 高危标签摘要**：受检人、核心风险暴露；阳性时叠加遗传/现症红色警示（如 BRCA1 + 吉早安阳性方向）。
2. **核心建议执行时间轴**（§7.2）：三档 **优先执行🔴 / 重要检查🟠 / 持续管理🟢**，LLM 按疾病严重程度划分，三档尽量均匀。
3. **循证"1+X"临床体检设计**（§7.1）：
   - 【1】基础必检套餐（含价，参考 KB `08-价格`）。
   - 【X】针对性精准加项表：列 = 异常指标/触发源（癌症附**后验概率/PPV**，有遗传突变则提示遗传证据）· 风险类别 · 推荐个性化检查 · 频次/间隔 · 参考价格 · 获益目的。
   - **异常范围口径**：癌症仅纳入**中等风险及以上**；若 >3 个则取风险因素 **TOP3**；癌症以外异常指标取自健康总结 API（**剔除癌症避免重复**）。检查项目/价格/周期严格依 KB。
4. **前沿液体活检专项**（§7.3）：
   - **阳性**：按 `-7` 红色警示看板；阳性 TOP 信号回灌时间轴 + 1+X 表作为触发源；行动闭环到物理病理确诊。
   - **阴性**：按 `-2`；并按"可降低当前高风险癌种多少风险评级"展示（沿用旧版阴性降风险逻辑）。
5. **组合套餐及预算推荐**（§7.4）：经济/全面（推荐）/前沿 三档，严格按模版约束填写。
6. **长期健康生活干预与专科建议**（§7.4）：按模版约束。
7. 页脚免责 + 版本（健康管理用途，不替代面诊）。

**渲染策略**：薄渲染器 + 一个 `report.json`（由前面分析填充，闭合词表）→ Jinja 模版。pos/neg 与 hereditary 走条件分支。

## 6. 个人健康档案（spec §1E）—— 自动保存更新

所有检查指标 + 时间节点 + 用户ID 结构化入库，按 `用户ID → 类别 → 指标 → 时间节点前后` 组织。位置沿用 `docudatabase/<person_id>/`。

**自动化（用户明确）**：档案库需**自动保存与更新**——每次跑完分析后自动把本次结构化指标按时间点合并入档（v1.3 的"先出 proposal 再人工确认入档"门槛在 v1.4 放宽为自动入档）。单指标纵向模块以此档案为唯一数据源。

## 7. 可选单指标纵向视图（spec §1F）—— 与档案库偶联

**决策**：作为**按需独立调用**的可选功能，**不作为主报告固定板块**，与个人健康档案库偶联：

- 输入：指标 key + person_id。
- 取数：从自动维护的健康档案读取该指标的全部时间点。
- 输出：**绘制趋势图**（折线/趋势）并展示，附趋势与现状解读。
- 形态：独立调用产出（独立小 HTML 或区块），默认不在主报告里自动出现。

## 8. 非协商约束（沿用 + 强化）

- **PUA / 闭合词表**：LLM 仅可从原文或用户答案填事实字段；不得编造 factor/cancer ID、概率、OR/RR/HR、LR、灵敏特异、筛查周期、建议。只用 orchestrator 派发的 allowlist。
- `evidence_text` 必须是来源 md 的**字面子串**。
- 苏格拉底问卷**不得预填/猜测/跳过**。
- 不得自行写脚本去改"应由 skill 生成的输出文件"；严格按 skill 流程跑（spec §3A）。
- 确定性检查点的填充不外包给子代理。

## 9. 分阶段计划（每阶段以真实用例为门槛）

> **验收门槛（spec §5）**：不得用简单示例测通过性。每个里程碑须用 `test/test_1`（test.pdf）与 `test/test_2`（多 PDF+图）跑**全流程**,评估：步骤调用完整性 + 结果完整性 + 复合正确性。问卷示例约定：选择题全选第一项，填空写"无"。

- **P0 知识架构对齐 + 缺口调研 + 数据库重塑**（§8/§4/§1A/§1B）→ verify：结构化库通过 schema 校验且引擎可加载；MD KB 可按需命中；缺口项有来源。
- **P1 管线改造为单报告**（§1D/§2）→ verify：三个旧 HTML 交付移除；健康总结/快照风险降为内部 JSON；orchestrator 跑到新报告检查点。
- **P2 唯一模版渲染器**（§7/§1C）→ verify：用 test_1（预期阴性向）+ test_2 渲染出含全部 6 板块的报告；pos/neg 与 hereditary 分支正确。
- **P3 健康档案 + 单指标纵向**（§1E/§1F）→ verify：入库结构正确；纵向按需调用产出趋势解读。
- **P4 双用例全流程验收**（§5）→ verify：test_1 + test_2 全流程通过三维评估。
- **P5 skill-creator + darwin 迭代**（§6）→ verify：两者评估跑完,据联合结果产出优化项并落地。

每阶段一个 worktree/分支，从 `v1.4` 切出，完成后并回 `v1.4`。

## 10. 备选方案（已考虑，未采纳）

- **结构化库全新 schema**：更干净，但需重写贝叶斯引擎，风险高、违背"外科化"。→ 采纳 D2 兼容方案。
- **保留多份 HTML 交付**：与 §1D"只出一个模版"冲突。→ 取消，降为内部分析。
- **纵向癌症风险预测保留**：spec §1F 明确取消。→ 改单指标纵向。
